# خطة منتج وتنفيذ NEXVARY Lingo
تاريخ البحث: 2026-10-14. حالة الوثيقة: خطة تأسيس أولية، وليست تقرير تنفيذ.
طلب المستخدم: فهم وبحث وتوقع المشكلات قبل الكود، نواة صغيرة قابلة للتغيير، توسع تدريجي واختبار مستمر، واجهة فاخرة.

## 1. تصور المنتج
برنامج يساعد البالغ الناطق بالعربية على فهم الإنجليزية واستخدامها في مواقف حقيقية.
النتيجة التعليمية المستهدفة: إنجاز مهمة تواصلية جديدة دون تلميحات، مع الاحتفاظ بالمهارة بعد مدة.
المسارات الأولية: الحياة اليومية، السفر، العمل. تجارة المعدات مسار تخصصي لاحق.
واجهة عربية وإنجليزية منفصلة عن لغة المنهج؛ لا نفترض أن إضافة ترجمة الواجهة تعني إضافة منهج لغة.
الجلسة الافتراضية المقترحة 10–15 دقيقة قابلة للتعديل، وليست وعدًا بزمن الإتقان.
لا نعد بطلاقة خلال مدة محددة أو بأن الطريقة ابتكار غير مسبوق.

## 3. حلقة التعلم
هدف واضح → مثال مفهوم → محاولة استرجاع → تلميح تدريجي عند الحاجة → تصحيح مركز → إعادة محاولة → مراجعة مؤجلة → موقف جديد.
التصحيح يحافظ على المعنى ويقبل البدائل الصحيحة، ولا يفرض مطابقة جملة واحدة.
لا نعاقب المتعلم على خطأ خدمة التعرف على الكلام.
النشاط الصوتي قابل للتخطي إلى نشاط نصي مع تسجيل أن مهارة التحدث لم تقاس.
المبتدئ يحصل على نماذج قصيرة؛ لا نبدأ بمحادثة مفتوحة فوق مستواه.
الإتقان لا يعتمد على نجاح فوري واحد أو النقاط وسلسلة الأيام.

## 4. وظائف النسخة الصغيرة
- إعداد الهدف والوقت، اختيار لغة الواجهة، بداية مناسبة للمبتدئ.
- ثلاث وحدات تجريبية: التعارف، طلب خدمة، السؤال عن سعر وضمان.
- جلسة كاملة بمساعدة تدريجية وإجابة نصية وتصحيح من محتوى منظم.
- حفظ التقدم ومحاولات الإجابة والمراجعة المستحقة محليًا.
- مراجعة واختبار سياق مختلف دون تلميحات.
- إعدادات الصوت والخصوصية وحذف التقدم.
- استماع إذا توفرت حزمة صوت مناسبة، مع شرح حالة عدم التوفر.

بعد نجاح هذه النواة: تدريب صوتي، تحديد مستوى تشخيصي أوسع، محادثة AI محدودة، تنزيل حزم، مسارات إضافية.
نؤجل الحسابات والمزامنة الاجتماعية والمكالمات متعددة الأطراف والأفاتار ثلاثي الأبعاد والاشتراكات حتى يثبت مسار التعلم.
لا نطلق تقدير مستوى CEFR كاعتماد رسمي؛ يظل تقديرًا داخليًا حتى تتم معايرته.

## 5. مواصفات الواجهة الفاخرة
الهوية: كحلي شديد العمق #080D18، سطح #111C2E، فضي #BEC8D5، أزرق #3D8BFF، ذهب محدود #D2AD67، نص فاتح #F3F6FA.
الألوان مقترحات، وتخضع لفحص التباين قبل اعتمادها.
الفخامة من التباعد والخط الواضح والتناسق؛ لمعان وحدود معدنية خفيفة دون خلفيات مزدحمة.
أيقونات vector ملونة من نظام واحد، مصحوبة بعناوين؛ لا Emoji كعناصر تنقل.
شريط تنقل: اليوم، المسار، التدريب، تقدمي. الإعدادات في زر واضح.
الرئيسية: هدف اليوم، زر بدء بارز، مراجعات مستحقة، بطاقة مهارة واحدة.
الدرس: تقدم، هدف، عبارة أو مشهد، منطقة إجابة، زر متابعة؛ إجراء أساسي واحد في كل خطوة.
التصحيح: ما نجح، تحسين محدد، مثال، إعادة المحاولة.
التقدم: فهم واسترجاع واستماع وتحدث كل على حدة، مع تمييز المهارات التي لم تقاس.
RTL للعربية وLTR داخل الجمل الإنجليزية؛ زر رجوع داخلي يحفظ الجلسة.
حالات loading/empty/error/offline/permission-denied مرئية ومفهومة بالعربية.
مساحة لمس لا تقل عن 48dp؛ تكبير خط 200% وشاشات ضيقة دون قص؛ دعم TalkBack وتقليل الحركة.
لا أزرار صامتة أو أيقونات متداخلة. قياسات الهوية النهائية تتبع مراجعة لقطات فعلية من التطبيق.

## 6. البنية المرنة
Kotlin وJetpack Compose؛ UI state أحادي الاتجاه وViewModel.
نبدأ بوحدتين: app وlearning-core، ثم نستخرج وحدات إضافية عند الحاجة الحقيقية.
learning-core لا يعتمد على Android أو شبكة؛ يحوي نماذج المهارات والجلسة ومحرك المراجعة.
طبقة البيانات في app عبر Repository؛ Room للتقدم والجلسات وDataStore لتفضيلات صغيرة.
القراءة الأساسية من قاعدة محلية؛ حزم الدروس ذات إصدار ومخطط واضح.
واجهات بديلة: LessonRepository، ProgressRepository، SpeechInput، SpeechOutput، ConversationProvider، Clock.
لا نجعل تغيير مزود AI أو الصوت يغيّر محرك التعلم.
الخادم يضاف عند تشغيل مزود مدفوع: يحتفظ بالمفتاح ويحدد المعدل والميزانية ويعيد نتيجة منظمة.
لا microservices ولا نشر خادم مطلوب للدرس المحلي الأول.

نماذج أولية:
- Skill: id, targetLanguage, type.
- Lesson: id, schemaVersion, contentVersion, skillIds, steps.
- Attempt: uniqueId, sessionId, skillId, timestamp, hintsUsed, modality, outcome.
- ReviewState: skillId, dueAt, lastAttemptAt, schedulingVersion.
- SessionCheckpoint: sessionId, lessonVersion, currentStep, status.
الإجابة النصية لا تمنح تلقائيًا تقدمًا في التحدث.
كل محاولة تحفظ مرة واحدة؛ التكرار أو تدوير الشاشة لا يضاعف التقدم.
حقن الساعة للاختبارات، ومراعاة تغيير الوقت والمنطقة الزمنية.
اختيار خوارزمية المراجعة بعد مقارنة البساطة والمعايرة والترخيص، وتوثيق إصدارها؛ لا نعد بدقة التنبؤ بالنسيان قبل اختبارها.

## 7. توقع المشكلات قبل التنفيذ
| الخطر | الوقاية | اختبار القبول |
|---|---|---|
| عدم توافق JDK/Gradle/AGP/Kotlin/Compose | تثبيت مجموعة موثقة، wrapper مع checksum، دون إصدارات dynamic | بناء نظيف من checkout جديد |
| غياب SDK أو الشبكة في CI | تثبيت محدد، timeouts، cache تحسين فقط | نجاح مع cache فارغ |
| تسريب مفاتيح | أسرار على الخادم أو CI، وعدم طباعتها | فحص المستودع والـAPK والسجلات |
| ضياع توقيع التحديث | مفتاح إصدار دائم ونسخة احتياطية محمية وبصمة موثقة قبل أول إصدار عام | تثبيت تحديث فوق نسخة سابقة مع حفظ البيانات |
| خلط debug وrelease | أسماء وبصمات واضحة وبناء release مستقل | فحص variant والتوقيع وversionCode |
| R8 يكسر serialization/Room | قواعد محددة واختبار release | تشغيل درس وحفظ واستعادة على release |
| فقدان جلسة بعد إغلاق النظام | checkpoint ومعاملة تخزين | قتل العملية واستئناف دون تكرار |
| ترقية قاعدة البيانات | migrations واختبار fixtures | ترقية تحتفظ بكل التقدم |
| مشاكل الميكروفون أو محرك الصوت | طلب الإذن وقت الاستخدام وإلغاء ومهلة وبديل نصي | رفض الإذن، انقطاع، ضوضاء، غياب خدمة |
| تقييم نطق مضلل | تحليل الصوت الفعلي ودرجة ثقة؛ ASR ليس تقييم فونيمات | عينات مقيمة بشريًا واختبار لهجات |
| تصحيح AI خاطئ أو متناقض | أهداف ومحتوى مراجعان، schema validation وحدود مخرجات | إجابات صحيحة بديلة ومدخلات عدائية |
| تكلفة وزمن AI | حدود ومهلة وميزانية واستخدام محلي أساسي | timeout و429 و5xx دون فقد جلسة |
| تنزيل حزمة ناقصة | checksum وكتابة مؤقتة وتبديل ذري وإرجاع | قطع التنزيل أو امتلاء التخزين |
| قص العربية والإنجليزية | موارد نصية وbidi مع تصميم responsive | RTL/LTR وتكبير خط وشاشة ضيقة |
| ادعاء تعلم غير مثبت | اختبارات مؤجلة ومواقف جديدة | مقارنة متساوية وقت التدريب |
| حقوق المحتوى | محتوى أصلي وسجل تراخيص وأصل كل ملف | تدقيق قبل إضافة أي corpus أو صوت |

خطة التوقيع ليست دليلًا على توفر مفتاح فعلي. اختيار الإصدارات الدقيقة وأدوات البناء ما زال يحتاج تحققًا قبل الكود.
المستودع عام: لا تُرفع تسجيلات المستخدمين أو بياناتهم أو ملفات keystore إليه.
الأذونات في CI أقل ما يلزم؛ البناء contents:read، والنشر بصلاحيات منفصلة.
عدم تشغيل كود PR غير موثوق مع أسرار النشر؛ تثبيت Actions إلى SHA مدقق عند الإنشاء.

## 8. خطة الاختبار والقبول
- unit: الجدولة، تلميحات/إتقان، بدائل الإجابة، عدم تكرار Attempt، سياق جديد، تواريخ وحدود.
- بيانات: صحة مخطط الدروس وروابط المهارات، ذرية الحفظ، migration.
- UI: بداية ودرس ومراجعة ورجوع واستئناف ورفض إذن؛ RTL وتكبير الخط.
- CI: تحقق محتوى → unit → lint → assembleDebug؛ ثم emulator → release smoke عند مرحلة الصوت.
- اختبار تركيب وتحديث release على جهاز فعلي قبل إعلان إصدار عام.
- أداء: نحدد الجهاز المرجعي أولًا ثم نقيس بدء التشغيل وسلاسة الدرس والذاكرة؛ لا أرقام نجاح دون قياس.
- التعليمية: اختبار قبلي ثم تدريبات متساوية المدة ثم اختبار فوري ومؤجل وموقف جديد؛ تقييم بشري أعمى للتحدث عند تجربة الفاعلية.
- لا يساوي اكتمال اختبارات الكود إثبات فعالية المنهج.

## 9. مراحل التنفيذ
| المرحلة | الناتج | بوابة الانتقال |
|---|---|---|
| 0: البحث والتصور | هذه الوثيقة ونطاق أولي | المخاطر والافتراضات مسجلة |
| 1: الأساس | wrapper وإصدارات مثبتة، learning-core، محتوى منظم، CI | unit + lint + build ناجحة |
| 2: مسار رأسي | هدف → درس → تصحيح → حفظ → مراجعة | دورة كاملة دون شبكة |
| 3: التصميم | هوية ومكونات وشاشات فعلية | لقطات RTL/LTR واختبارات رجوع وتكبير |
| 4: الصوت | استماع وتسجيل وتعامل مع الأخطاء | مصفوفة الأذونات والتوفر والجودة |
| 5: AI | مزود منفصل وخادم محدود التكلفة | schema/timeouts/cost/privacy مثبتة |
| 6: النسخة التجريبية | حزم إضافية وتقارير خطأ وتحديث | release smoke + حفظ البيانات عند التحديث |
| 7: التوسع | معايرة المنهج ولغات ومسارات جديدة | دليل تعلم واستخدام يستحق التوسع |

المراجعة المستمرة: كل تعديل يسجل المشكلة والدليل والقرار ونتيجة التحقق. يعاد البحث عندما تتغير مكتبة أو خدمة أو تظهر مشكلة؛ لا نضيف ميزة لأنها رائجة فقط.
حالة التنفيذ الآن: تخطيط وبحث مكتملان كأساس أولي؛ الكود والاختبارات والبناء والواجهة المرئية لم تنفذ بعد.
